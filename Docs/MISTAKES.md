# Mistakes

Bugs I introduced or missed, what actually caused them, and what stops the same
class recurring. Kept because several of these were the same mistake wearing a
different hat, and the pattern is more useful than the list.

Newest first.

---

## Prompt and input gated on different conditions

**Symptom:** "I can see the interaction but I can't burn the bodies."

`Interactor` set `Prompt` *before* the `Cursor.lockState` check and read input
*after* it. Whenever the Game view lost focus the cursor unlocked, so the prompt
still drew and holding did nothing.

**Cause:** two halves of one feature guarded by different conditions.

**Fix:** one gate, `Time.timeScale > 0`, used for both. Cursor capture is the
editor's business, not the player's.

**Rule:** if a thing is shown and a thing is done, they take the same condition.

## An unlockable gate

**Symptom:** no burn prompt on any body, ever.

Bodies unlocked only once the monster had seen the player. The monster spawned
141m away with a village in between and sees 85m, so the gate could only open if
its patrol happened to bring it close with clear line of sight. Often never.

**Cause:** a condition whose reachability I never checked. I verified the
mechanism and not the situation.

**Fix:** the encounter counts both ways -- the player laying eyes on it also
unlocks -- and it spawns 40m away.

**Rule:** for any gate, ask what specifically makes it open, and confirm that
thing can happen in the first minute of play.

## Raycast against objects lying on the ground

**Symptom:** no interaction with bodies or ammo boxes.

`Physics.Raycast` returns the nearest hit. Bodies lie on the floor and ammo
boxes were 18cm tall, so the terrain was nearly always nearer and the
interactable was never considered. The body triggers were also centred at
y = -0.05, half buried.

**Fix:** sphere-cast, collect every hit, take the nearest *interactable*; solid
geometry blocks only when meaningfully in front. Triggers sized and seated
properly.

## Reload that could never complete

```csharp
public bool Reloading => Time.time < reloadUntil;
if (Reloading) { if (Time.time >= reloadUntil) Refill(); }
```

Inside the branch the completion condition is by definition false. The magazine
never refilled.

**Cause:** deriving state from a clock and then testing the same clock inside it.

**Fix:** an explicit `reloading` flag.

**Rule:** a derived property and a branch on its own inputs do not mix.

## Converting every material the same way

**Symptom:** falling leaves rendered as solid blocks.

The Standard-to-URP converter sent *every* built-in material to `URP/Lit`,
particle materials included. A lit opaque shader on a particle draws a solid
quad.

**Fix:** collect every material any `ParticleSystemRenderer` uses, across
prefabs and scenes, and route those to `URP/Particles/Unlit` instead.

**Rule:** a bulk conversion needs to know what each thing is for.

## Writing to an imported sub-asset

**Symptom:** the gun stayed untextured after I said it was fixed.

I set `_BaseMap` on the material embedded in the FBX and called it done. An
imported sub-asset is regenerated by the importer, so the change was discarded
on the next reimport.

**Fix:** create a real `.mat`, wire it, and `AddRemap` the model onto it.

**Rule:** you cannot edit an imported asset in place. Extract, then remap.

## Trusting `isSupported`

**Symptom:** magenta water, rocks, barn, bushes and jeep, through six scans that
all reported the scene clean.

Flooded Grounds ships custom Built-in-pipeline shaders. Under URP they report
`isSupported == true` and simply do not draw. No data check can see this.

**Fix:** rendered the camera to a PNG, looked at it, then bisected by hiding
groups of renderers and re-counting pink pixels until one material was left.

**Rule:** when the report and the screen disagree, the screen is right. Render
and look before insisting the data is clean. This one cost the most time of
anything here, and the tool to solve it existed the whole way through.

## Rebuilding the wrong thing, twice

Twice I left the Editor on a different scene after a verification pass, so what
was open was not what I had just built. Both times it looked like the work had
vanished.

**Rule:** end every build by opening the scene the work is in, and say which one
is open.

---

## Legacy input module under an Input-System-only project

`EnsureEventSystem` added `StandaloneInputModule`, which reads the legacy `Input`
class. With `activeInputHandler: 1` every read throws inside `EventSystem.Update`,
killing the UI event loop before any click is dispatched. Every button in the
game was dead.

A second version of the same bug: the helper returned early when *any*
EventSystem existed, so a scene inherited from an asset pack kept the pack's
legacy module.

**Rule:** check the project's input handler before touching UI, and fix what you
find rather than skipping when something is already there.

## Things that were not mistakes, recorded so they are not re-investigated

- Particle renderers in `renderMode = None` legitimately have no material.
- The parent system of the Vefects fire and blood prefabs is a controller that
  draws nothing; its null material is by design.
- Unity does not tick play mode while its window is unfocused, so play-mode
  behaviour cannot be verified from the CLI. Run In Background is now on, and it
  still is not reliable. Pacing and feel are Kartik's to judge.
